# Items A (deck, frags, shop, loot) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Thirteen deck items the player loads or uses, frags earned from drops and paid on a first win, a working Shop tab, loot on hard levels, Flatline rescue with Overclock, and Reset progress.

**Architecture:** Item rules are pure, in a new `src/items.js` (table, unlocks, loot, deck bookkeeping, hex geometry, every effect as "what would this item do here"). `src/core.js` gets one shared settle step after any shot, a pending-frags counter and item firing through `S.load`. `src/ui.js` draws and wires it; item icons live in `src/icons.js` as SVG path strings usable by DOM and canvas. Item bubbles on the board and the bot are Plan B (`docs/superpowers/plans/2026-10-26-items-b.md`).

**Tech Stack:** Vanilla ES modules, canvas 2D, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-26-items-shop-design.md`

## Global Constraints

- Vanilla HTML, CSS, ES modules; no build step, no dependencies.
- `localStorage` keys start with `splice-` (new: `splice-deck`).
- No visible text in code; every string in `lang/en.json`, sentence case, no em-dashes, typographic apostrophes (’). `tests/lang.test.mjs` requires each key used in `ui.js` as a literal `t('key'`, and every key in `en.json` used.
- Pure rules stay in `src/` without DOM or storage; no `Math.random` in `src/`; all draws seeded with `mulberry32(hash(...))`.
- Fairness: packets are dealt only from colours on the board.
- Reduced motion: effects show at once.
- Portrait phones, no horizontal scroll.
- `core.js`, `levels.js`, `bot.js`, `hosts.js` import each other; uses of imported names stay inside function bodies. `items.js` follows the same rule.
- Run `node --test` after every task. After Task 2, `node tools/sim.mjs 1,3,5,10,25 1` must print exactly what it printed before Task 2 (the refactor must not change play).
- Conventional Commits, no `Co-Authored-By` or "Generated with" lines.

## Ruling on a spec gap

The spec never says whether firing a deck item costs a shot. The brainstorm playback said it does not, and the owner did not object. **Firing a loaded item does not use up a shot** (`S.shots` unchanged). Overclock adds 5.

## Review Focus

1. A reload mid-level with an item loaded, an ICE breaker running, or pending frags: all must come back (they are in the save). Test in Task 2.
2. A win on a replayed level (below best) must pay nothing; a reload of a won best-level board must not pay twice. Test in Task 4 (pure `payout`).
3. Corrupt or hand-edited `splice-deck` (negative counts, unknown ids, strings): falls back safely, never crashes. Test in Task 1.
4. An item effect that clears the last colour bubbles wins the level; one that removes `S.cur`'s colour re-deals it. Test in Task 2.
5. Buying with exactly the price, and with one frag too few. Test in Task 1.

### Task 2: Item effects and the shared settle step (`src/items.js`, `src/core.js`)

**Files:**
- Modify: `src/core.js` (`fire`, `toSave`, `fromSave`, `validSave`, `startState`)
- Modify: `src/items.js`
- Test: `tests/items.test.mjs`, `tests/core.test.mjs`

**Interfaces:**
- Consumes: `ITEMS`, `item` (Task 1).
- Produces:
  - In `core.js`: `settle(S, popped, extra = [])` → `{ popped, dropped, points }`. Removes `popped` keys from the grid, drops what is no longer `connected`, adds `dropped.length` to `S.frags`, adds `points = 10 * popped.length + 10 * dropped.length ** 2` to `S.score`, runs the existing scroll rule, then the existing re-deal rule for `S.cur`/`S.next`. `extra` is unused in Plan A (Plan B passes item bubbles). `fire(S, ang)` keeps its signature and return value and calls `settle` for its pop; with `S.load` set it fires the item instead (below).
  - New state fields, all saved and restored: `S.frags` (pending frags this attempt, starts 0), `S.load` (loaded item id or `null`), `S.breaker` (ICE breaker shots left, starts 0). `validSave` accepts them when present (`frags`, `breaker` non-negative integers; `load` `null` or a shot item id) and stays valid when they are missing (old saves); `fromSave` defaults them to `0`, `null`, `0`. Save version stays `v: 1`.
  - In `items.js`, hex helpers on odd-r offset rows (odd rows sit half a cell right, as `nbrs` in `core.js`): `dist(cols, a, b)` (hex steps between keys `a` and `b`), `ray(cols, k, d, n)` (up to `n` keys from `k` in direction `d` of 6, off-board cells skipped by stopping the ray), `within(cols, k, n)` (keys of all on-board cells with `dist <= n`).
  - `hits(S, id, ang)` → `{ pts, cell, clear: Set<key>, recolour: Map<key, colour>, land: colour|null }` or `null` (aim down or nothing hit). Pure, does not touch `S`. `pts` is the flight path for the animation; `cell` the landing cell (`null` for Pierce); `clear` the bubbles removed by the effect itself; `recolour` the bubbles that change colour; `land` the colour of a bubble the item leaves in `cell`, or `null` if it leaves none. Used by the preview and by `fire`.
  - `fire` with `S.load`: `h = hits(S, S.load, ang)`; if `null` return `null`; apply `recolour`, set `cell` to `land` if not `null`, then `settle(S, [...h.clear, ...pops])` where `pops` is the normal pop of the landed bubble when the item is Wildcard; `S.load = null`; `S.shots` unchanged (ruling above); `S.cur`/`S.next` unchanged except for the re-deal rule. Returns `{ pts, cell, popped, dropped, points, recolour }`.
  - `useItem(S, id, arg)` → `true` if applied: `overclock` `S.shots += 5`; `decrypt` sets `S.cur = arg` if `arg` is a colour on the board; `icebreaker` `S.breaker = 5`; shot ids set `S.load = id` (only if `S.load` is `null`); `rollback` is UI-side (Task 3), returns `false` here.
  - `unload(S)` → `S.load = null`.

Effect rules, all deterministic (spec, Builder's calls):

| id | uses `trace` landing | `clear` | `recolour` / `land` |
|---|---|---|---|
| bomb | yes | every bubble in `within(cols, cell, 2)` | `land: null` |
| sweep | yes | every bubble in the landing row | `land: null` |
| star | yes | every bubble on `ray(cols, cell, d, 4)` for all 6 `d` | `land: null` |
| lightning | yes | path: from `cell`, repeatedly step to the occupied neighbour in the row above (`r - 1`) not yet taken; of two, the one whose column is nearer the landing column, then the left one; stop after 8 bubbles or when neither upper neighbour holds a bubble | `land: null` |
| purge | yes | every bubble with the hit colour in rows `S.top` to `lossRow(S)` | `land: null` |
| virus | yes | none | every bubble in `within(cols, cell, 4)` → hit colour; `land: hit colour` |
| wildcard | yes | none from the effect itself | `land`: the colour among occupied neighbours whose same-colour group (flood from those neighbours) is biggest; tie → the one whose pop (group + the landed bubble, if 3 or more) drops more; no occupied neighbour → `S.cur`. Then the landed bubble pops as normal if its group reaches 3 |
| rainbow | yes | for each colour among occupied neighbours: that colour's group (flood from the touched ones) if it has 2 or more bubbles | `land: null` |
| pierce | no: own path | the first 10 bubbles the path passes within `HIT` of, as `trace` steps (0.25 radii, wall bounces); ends at 10 or at the ceiling (`y <= 1`) | `cell: null`, `land: null` |

"Hit colour" (virus, purge): the colour of the occupied neighbour of `cell` nearest the last point of `pts`; no occupied neighbour (landing at the ceiling alone) → `clear` and `recolour` empty, `land: S.cur` for virus.
