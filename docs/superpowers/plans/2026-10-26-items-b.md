# Items B (item bubbles, chains, bot) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Some levels have item bubbles hanging in the cluster; a packet touching one sets it off, clearing items chain, and the bot plays them so the shot limit assumes their use.

**Architecture:** Item bubbles are grid values from `ITEM_BASE` (6) up, so every bubble rule (connection, loss line, scrolling) keeps working and only colour rules learn to skip them. One pure `resolve` in `src/items.js` works out a whole shot (normal pop, item bubbles set off, chains, recolours) on a copy; `fire`, the aim preview and the bot all use it. Builds on Plan A (`docs/superpowers/plans/2026-10-26-items-a.md`), which must be done first (same branch).

**Tech Stack:** Vanilla ES modules, canvas 2D, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-26-items-shop-design.md`

## Global Constraints

- Everything in Plan A's Global Constraints holds.
- Design goal 3: packets are dealt only from colours on the board; item bubbles are never dealt and never count as a colour.
- The bot's cost stays near today's (about 0.15 s early, up to about 1 s on the largest levels, Mac, node). Measure with `node tools/sim.mjs 5,10,30,40,45,70 1` before and after (the `ms/shot` column).
- Rerun `node --test` and the sim after rule changes.

## Review Focus

1. A level whose only remaining bubbles are item bubbles: it is won, leftover item bubbles fall, the sheet shows. Test in Task 2.
2. An old `v: 1` save after the update: restarts its level (fails kept), never crashes. Test in Task 2.
3. Two item bubbles that set each other off, and one that would be reached twice: each goes off once, no endless loop. Test in Task 3.
4. A chain that wipes out `S.cur`'s colour: re-dealt. Test in Task 3.
5. An item bubble at or below the loss line counts for losing like any bubble. Test in Task 2.

### Task 2: Colour rules skip item bubbles; saves v2 (`src/core.js`)

**Files:**
- Modify: `src/core.js` (`deal`, `reachable`, `won`, `settle`, `toSave`, `validSave`), `src/items.js` (`hits`: colour-based effects skip item bubbles)
- Test: `tests/core.test.mjs`, `tests/items.test.mjs`

Rules:
- `deal` and `reachable` count colour bubbles only (`all`, `near`, `vis`, `pairs`).
- `won(S)`: no colour bubble left. In `settle`, when no colour bubble is left, every remaining item bubble is removed as dropped. Dropped item bubbles pay no frags (`S.frags` counts colour bubbles only); `points` counts all.
- `lost(S)` unchanged: any bubble, item bubbles included, at or below `lossRow(S)`.
- Re-deal: `has` is the set of colours on the board, without item values.
- `hits` in Plan A: Wildcard, Rainbow, Purge, Virus look only at colour bubbles (groups, hit colour, recolour targets); Bomb, Sweep, Star, Lightning, Pierce clear item bubbles in their area too (Lightning steps through them as bubbles).
- Saves: `toSave` writes `v: 2`; `validSave` accepts `v: 2` only, grid values `0 .. ITEM_BASE + SHOTS.length - 1`, `cur`/`next`/`hist` colours only. A `v: 1` save fails and `load()` in `ui.js` already restarts its level with its fails (and, since Plan A's fix wave, gives a loaded item back to the deck).
- `isColour` (from Plan A's fix wave, `core.js`) becomes `v => v >= 0 && v < ITEM_BASE`-equivalent; every colour rule above uses it.

### Task 3: Setting off item bubbles and chains (`src/items.js`, `src/core.js`)

**Files:**
- Modify: `src/items.js`, `src/core.js` (`fire`)
- Test: `tests/items.test.mjs`

**Interfaces:**
- Produces: `resolve(S, shot)` → `{ pts, cell, clear: Set, recolour: Map, popped: Set, fired: [key...] }`, pure (works on a copy of the grid). `shot` is `{ ang }` for a normal packet (colour `S.cur`) or `{ ang, id }` for a deck item. `fire` applies it (both kinds) and returns `{ pts, cell, popped, dropped, points, recolour, fired }`; `hits` (Plan A's preview) becomes a thin call of `resolve` so the preview includes chains.

Rules (spec, Item bubbles and Builder's calls):
- Touch: item bubbles that are neighbours of the landed cell; for Pierce, every item bubble its path passes (they are cleared and set off). Several touched: all go off.
- Order: the shot's own effect first (normal pop of the landed packet, or the deck item's effect), then the touched item bubbles in key order, then chains breadth first; each item bubble goes off at most once (a `fired` set); all clears and recolours are applied, then one `settle` drops what is cut loose.
- An item bubble goes off at its own cell `k` and is removed. Effect at `k`: Bomb `within(k, 2)`; Sweep row of `k`; Star rays from `k`; Lightning upward from `k`; Pierce from `k`'s centre in the direction the shot was travelling when it landed (last segment of `pts`), same 10-bubble rule; Wildcard: `k` becomes a colour bubble by the Wildcard rule and pops if its group reaches 3; Rainbow: groups of 2 or more touching `k` pop; Virus: recolour `within(k, 4)` colour bubbles to the hit colour, `k` becomes that colour; Purge: clear the hit colour on screen.
- Hit colour for an item bubble: the colour of the packet that touched it; for a deck item packet or a chain, the colour of the first colour neighbour of `k` in `nk(cols, k)` order; none → Virus and Purge do nothing (the bubble is still removed).
- Chains: item bubbles inside the `clear` area of Bomb, Sweep, Star, Lightning, Pierce go off too. Item bubbles never pop in a colour pop (they have no colour); Wildcard, Rainbow, Purge, Virus never set off others.
- After resolve, the re-deal rule and the win rule of Task 2 apply.
- Keep Plan A's final-review rules (on the branch since its fix wave): a deck item whose effect changes nothing (`clear`, `recolour` and, for Wildcard/Rainbow, `popped` all empty) gives `null`, so it cannot be fired and stays loaded; Lightning's first step goes to the touched neighbour with the lowest row; colour checks use `isColour` from `core.js` (Decrypt included).
- The preview outlines `popped` as well as `clear` (Wildcard and Rainbow then show what they pop; Plan A left Wildcard without a preview).

- [ ] **Step 1: Write the failing tests** (Review Focus 3, 4): `'a packet touching an item bubble sets it off'`; `'two touched item bubbles both go off'`; `'a bomb inside another bomb\'s blast chains'`; `'mutual chain: each goes off once'` (two bombs in each other's radius: `fired.length === 2`); `'an item bubble in a colour pop does not go off'` (impossible by construction: assert a pop next to an untouched item bubble leaves it, unless it falls); `'a falling item bubble does nothing'`; `'virus bubble spreads the colour of the packet that hit it'`; `'pierce bubble continues in the shot\'s direction'`; `'a chain that removes the current colour re-deals it'`; `'the preview from hits equals what fire does'` (for several random seeded boards and angles, `hits(...).clear` equals the keys `fire` removed minus the dropped ones).
- [ ] **Step 2: Run** `node --test` — expected: FAIL.
- [ ] **Step 3: Implement** `resolve`, switch `fire` and `hits` to it.
- [ ] **Step 4: Run** `node --test` and the sim (`node tools/sim.mjs 1,3,5,10,25 1`) — expected: all tests pass; the sim wins every level.
